# 🖥️ Windows CLI Giga Agent

CLI-агент для терминала на базе GigaChat API. Понимает задачи на естественном языке, читает и пишет файлы, выполняет команды, ведёт диалог с историей. Один Python-файл, без фреймворков.

## ✨ Возможности

- 🛠️ **Инструменты**: `read_file`, `write_file`, `edit_file`, `list_dir`, `run_shell`, `install_package`
- 📦 **Установка пакетов** через системный пакетный менеджер: `winget`, `choco`, `apt`, `dnf`, `pacman`, `brew`
- ✅ **Подтверждение опасных команд** — `run_shell` и `install_package` спрашивают `y/n` перед выполнением
- ✏️ **Точечная правка файлов** через `edit_file` — замена по уникальному фрагменту
- 🔄 **Обновление PATH** без перезапуска терминала
- 🎨 **Цветной вывод** — ввод белый, ответы зелёные, ошибки красные, вызовы инструментов жёлтые
- 🏷️ **ASCII-логотип** при запуске
- 🛡️ **Защита от галлюцинаций** — установка только через `install_package`, не через `run_shell`
- 🧩 **Fallback-парсер** — понимает несколько форматов JSON-ответа модели
- 🌍 **Кроссплатформенность** — Windows, Linux, macOS

## 📋 Требования

- 🐍 Python 3.9+
- 🔑 Аккаунт на [developers.sber.ru](https://developers.sber.ru/portal/products/gigachat) с доступом к GigaChat API

## 📥 Установка

```bash
pip install gigachat colorama
```

Скачай `windows_cli_giga_agent.py` и положи в удобную папку.

## ⚙️ Настройка

Получи **Authorization key** в личном кабинете developers.sber.ru (раздел GigaChat API → «Получить ключ»).

**Windows (PowerShell):**

```powershell
setx GIGACHAT_CREDENTIALS "твой_authorization_key"
setx GIGACHAT_SCOPE "GIGACHAT_API_PERS"
```

**Linux / macOS:**

```bash
export GIGACHAT_CREDENTIALS="твой_authorization_key"
export GIGACHAT_SCOPE="GIGACHAT_API_PERS"
```

После `setx` перезапусти терминал.

> ⚠️ Ключ даёт доступ к платным токенам. Не коммить его в репозиторий и не публикуй в чатах. Если ключ утёк — перевыпусти его в ЛК.

## 🚀 Запуск

```bash
python windows_cli_giga_agent.py
```

## 🧰 Инструменты

| Инструмент | Описание |
|---|---|
| 📖 `read_file(path)` | Прочитать файл, до 20 000 символов |
| 💾 `write_file(path, content)` | Записать файл (перезапись), с нормализацией экранирования |
| ✏️ `edit_file(path, old, new)` | Заменить уникальный фрагмент `old` на `new` в файле |
| 📂 `list_dir(path)` | Список файлов в директории, до 200 записей |
| ⚡ `run_shell(command)` | Выполнить команду с подтверждением `y/n` |
| 📦 `install_package(package)` | Установить пакет через системный пакетный менеджер |

## 🔍 Как это работает

1. 💬 Пользователь пишет задачу на естественном языке.
2. 📡 Скрипт отправляет запрос в GigaChat API с описанием доступных инструментов.
3. 🤖 Модель отвечает JSON-объектом: либо вызов инструмента, либо финальный ответ.
4. ⚙️ Скрипт выполняет инструмент локально и возвращает результат модели.
5. 🔁 Цикл повторяется до финального ответа или лимита в 15 шагов.

## 🔒 Безопасность

- ✅ **Подтверждение команд** — `run_shell` и `install_package` показывают команду и спрашивают `y/n`. По умолчанию отменяется.
- 🚫 **Изоляция установки** — `run_shell` блокирует `apt-get install`, `winget install`, `brew install` и т.п. Установка идёт только через `install_package`.
- 🔢 **Лимит шагов** — 15 итераций на один запрос.
- ✂️ **Обрезка вывода** — результаты инструментов режутся до 20 000 символов.

Агент **не** ходит в интернет и **не** скачивает файлы по URL — только установка через штатный пакетный менеджер с подтверждением.

## ⚠️ Известные ограничения

- 🎲 **GigaChat-2-Max не всегда следует формату JSON.** Модель может прислать `{"write_file": {...}}` вместо `{"tool": "write_file", "args": {...}}`, добавить текст вокруг JSON или выдать несколько объектов подряд. Парсер это обрабатывает, но поведение модели непредсказуемо.
- 🔧 **Function calling через нативный API не используется** — вместо этого строгий JSON-протокол.
- 🔄 **PATH в интерактивном терминале** обновляется только после перезапуска (сам агент видит новый PATH через `refresh_path()`).
- ⏳ **Установка крупных пакетов** может занять больше 15 минут — таймаут `install_package` 900 секунд.

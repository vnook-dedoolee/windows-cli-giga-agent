## ⌨️ Многострочный ввод и вставка

Для больших текстов (условий задач, HTML, кусков кода) используй один из способов:

1. **`:paste`** — набери `:paste` и нажми Enter. Откроется Блокнот (или `nano`/`open -e` на Linux/macOS). Вставь любой текст, сохрани (Ctrl+S) и закрой окно. Скрипт прочитает весь текст как один запрос и **не будет** выполнять его построчно.

2. **Backslash-режим** — если первая строка заканчивается на `\`, скрипт будет читать ввод до строки, состоящей только из `\`.

3. **Тройные кавычки / `:end`** — начни ввод с `"""` или `:end` и закончи такой же строкой.

4. **Пайп/редирект** — `python windows_cli_giga_agent.py < task.txt`. Если stdin не TTY, весь поток читается одним запросом, без построчной обработки.

## 🧰 Инструменты

| Инструмент | Описание |
|---|---|
| 📖 `read_file(path)` | Прочитать файл, до 20 000 символов (далее — маркер `[N chars]`) |
| 💾 `write_file(path, content)` | Записать файл (перезапись), с нормализацией экранирования |
| 📥 `append_file(path, content)` | Дописать текст в конец файла (для конвейера) |
| 🧩 `insert_inside_class(path, content)` | Вставить код перед последней `}` — удобно для добавления методов в класс |
| ✏️ `edit_file(path, old, new)` | Заменить уникальный фрагмент `old` на `new` в файле |
| 📂 `list_dir(path)` | Список файлов в директории, до 200 записей |
| ⚡ `run_shell(command)` | Выполнить команду с подтверждением `y/n` |
| 📦 `install_package(package)` | Установить пакет через системный пакетный менеджер |
| 🌐 `fetch_url(url)` | Скачать страницу и вернуть чистый текст (BeautifulSoup вырезает скрипты/стили). Если текст >10 000 символов — сохраняет в `temp_page.txt` |
| 🔍 `web_search(query)` | Поиск через DuckDuckGo Lite, возвращает до 5 ссылок с описанием |
| 📜 `git_diff()` | Показать текущие изменения в git (`git diff` или `git diff --cached`) |

## 🔁 Конвейер: бесконечные файлы

GigaChat физически не может выдать длинный файл за один ответ — упирается в `max_tokens=2000`. Чтобы обойти это, встроен **конвейер**:

1. Модель вызывает `write_file` для первого куска (например, структуры класса).
2. Скрипт сохраняет и возвращает модели `OK: записано N символов`.
3. Скрипт сам добавляет сообщение: *«Если не дописал — вызови `append_file` с продолжением»*.
4. Модель вызывает `append_file` — код дописывается в конец.
5. Для добавления методов в класс есть `insert_inside_class` — он вставляет код перед последней `}`.
6. Когда всё готово, модель отвечает `{"answer": "Готово"}`.

Так можно собирать файлы любого размера: не ограничено лимитом токенов одного ответа.

## 📜 Работа с git

Если ты просишь агента написать комментарий для коммита, он:
1. Вызывает `git_diff`.
2. Получает реальные изменения кода.
3. Генерирует осмысленный комментарий в стиле Conventional Commits (`feat:`, `fix:`, `docs:`) **на русском языке**.

Пример:

```text
Вы: Напиши комментарий для пуша

  [tool] git_diff {}
  [result] === UNSTAGED CHANGES (git diff) ===
diff --git a/agent.py b/agent.py
...

GigaChat: feat: добавлен конвейер кода, сетевые инструменты и вставка через :paste

- feat: append_file и insert_inside_class для сборки длинных файлов
- feat: fetch_url и web_search
- fix: принудительный UTF-8 в консоли Windows
- fix: умный парсер для обрезанного JSON
- docs: обновлён README
```

## 📄 Умная обрезка больших страниц

Если `fetch_url` скачал страницу, которая содержит больше 10 000 символов, скрипт **не пихает** её в модель целиком (иначе GigaChat отвечает «Результат слишком большой, обработка прервана»). Вместо этого:
1. Текст сохраняется в файл `temp_page.txt`.
2. Модели возвращается сообщение: *«Страница загружена, но она слишком большая. Текст в `temp_page.txt`»*.
3. Модель вызывает `read_file('temp_page.txt')` и читает нужный фрагмент (или использует `run_shell` с `grep`/`findstr` для поиска по ключевому слову).

## 🔍 Как это работает

1. 💬 Пользователь пишет задачу на естественном языке.
2. 📡 Скрипт отправляет запрос в GigaChat API с описанием инструментов и жёсткими правилами формата.
3. 🤖 Модель отвечает JSON-объектом: либо вызов инструмента, либо финальный ответ.
4. 🧩 **Умный парсер** разбирает ответ в нескольких форматах:
   - `{"tool": "name", "args": {...}}` — стандартный,
   - `{"write_file": "path", "content": "..."}` — плоский fallback,
   - обрезанные ответы — дописывает скобки и кавычки, чтобы спасти данные.
5. ⚙️ Скрипт выполняет инструмент локально и возвращает результат модели.
6. 🔁 Цикл повторяется до финального ответа или лимита в 50 шагов.
7. 🛡️ **Блокировка отказов** — если модель отвечает `answer` с фразами «уточни», «предоставь», «не могу» — скрипт не показывает это пользователю, а возвращает модели настойчивое требование действовать через tool.

## 🔒 Безопасность

- ✅ **Подтверждение команд** — `run_shell` и `install_package` показывают команду и спрашивают `y/n`. По умолчанию отменяется.
- 🚫 **Изоляция установки** — `run_shell` блокирует `apt-get install`, `winget install`, `brew install` и т.п. Установка идёт только через `install_package`.
- 🔢 **Лимит шагов** — 50 итераций на один запрос.
- ✂️ **Обрезка вывода** — результаты инструментов режутся, при обрезке показывается маркер `... [N chars]` с полным размером. Лимиты настраиваются через переменные окружения.

## 🎛️ Настройка лимитов через окружение

Все лимиты обрезки можно менять без правки кода:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `GIGA_LIMIT_READ_FILE` | 20000 | Максимум символов из `read_file` |
| `GIGA_LIMIT_SHELL_OUT` | 20000 | Максимум вывода `run_shell` и `git_diff` |
| `GIGA_LIMIT_INSTALL_OUT` | 20000 | Максимум вывода `install_package` |
| `GIGA_LIMIT_WEB_OUT` | 15000 | Максимум текста из `fetch_url` |
| `GIGA_LIMIT_TOOL_PRINT` | 300 | Сколько печатать в консоль от результата |
| `GIGA_LIMIT_TOOL_TO_MODEL` | 8000 | Сколько отдавать модели в историю |
| `GIGA_LIMIT_RAW_MODEL` | 500 | Сколько печатать от «сырого» ответа модели |

Пример:

```powershell
setx GIGA_LIMIT_READ_FILE 100000
setx GIGA_LIMIT_WEB_OUT 50000
```

## 🌐 Работа с сетью

- 🔍 `web_search` использует `lite.duckduckgo.com` — не требует API-ключей, но иногда может упираться в капчу.
- 🌐 `fetch_url` скачивает страницу через `requests`, чистит HTML через BeautifulSoup, убирая `<script>`, `<style>`, `<nav>`, `<footer>`, `<header>`.
- 🚫 Сайты с JS-рендерингом (LeetCode, NeetCode, современные SPA) могут отдавать `403` или пустой текст — в этом случае копируй текст руками и вставляй через `:paste`.

## ⚠️ Известные ограничения

- 🎲 **GigaChat-2-Max не всегда следует формату JSON.** Модель может прислать `{"write_file": {...}}` вместо `{"tool": "write_file", "args": {...}}`, добавить текст вокруг JSON, использовать тройные кавычки `"""` или обрываться на полуслове. Парсер и `system_prompt` борются с этим, но поведение модели непредсказуемо.
- 🔧 **Function calling через нативный API не используется** — вместо этого строгий JSON-протокол + fallback-парсер.
- 🔄 **PATH в интерактивном терминале** обновляется только после перезапуска (сам агент видит новый PATH через `refresh_path()`).
- ⏳ **Установка крупных пакетов** может занять больше 15 минут — таймаут `install_package` 900 секунд.
- 🧠 **Модель не считает символы и токены.** Если сказать «пиши по 1000 символов», она не сможет это соблюсти. Конвейер рассчитан на то, что модель отдаёт максимум в рамках `max_tokens=2000` и продолжает через `append_file`.
- 🚫 **Сайты с защитой от ботов** (Cloudflare, LeetCode) не открываются через `fetch_url` — используй `:paste`.
- 🧩 **Авто-закрытие скобок** для незавершённых ответов не используется — вместо этого модель обязана добавлять недостающие методы через `insert_inside_class`, а за оборванный ответ парсер вернёт сообщение о нарушении формата.
- 📜 **git_diff** работает только если в системе установлен `git` и текущая папка является git-репозиторием.
